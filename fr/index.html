from enforcecore import enforce
from langgraph.prebuilt import create_react_agent

@enforce(policy="policy.yaml")
def run_agent(user_input: str) -> str:
    agent = create_react_agent(model, tools)
    result = agent.invoke({"messages": user_input})
    return result["output"]

name: "production"
on_violation: "block"

rules:

    - send_email

    - read_file

    - calculator

    enabled: true
    categories: [email, phone, ssn, credit_card]

  network_control:
    allowed_domains: ["api.openai.com"]

  resource_limits:
    max_cost_usd: 5.00

La pile d'enforcement. Un seul décorateur.

Chaque composant fonctionne indépendamment ou ensemble. Ajoutez ce dont vous avez besoin — des vérifications de politique à la conformité complète.

⚙️

Moteur de Politique

Politique YAML déclarative — autoriser/refuser les actions, exiger des approbations, définir des seuils de confiance. Évaluée de manière déterministe avant chaque appel d'outil.

policy = Policy.from_file("policy.yaml")
engine = PolicyEngine(policy)
result = engine.evaluate_pre_call(context)
# result.is_allowed | result.reason
🔒

Rédacteur PII

Détecte et rédige 11 catégories de PII — email, téléphone, SSN, carte de crédit, nom, adresse et plus — par regex et Presidio NER optionnel.

redactor = Redactor(strategy=PLACEHOLDER)
result = redactor.redact(agent_output)
# result.text → "[EMAIL]", "[PHONE]"
🔗

Auditeur Merkle

Chaque action d'agent est hachée et chaînée dans un arbre Merkle avec injection de hash externe (Merkle Bridge). Infalsifiable. Exportable. Vérifiable indépendamment.

auditor = Auditor()
auditor.record(tool_name="search", decision="allowed")
# Verify: verify_trail("trail.jsonl")
🛡️

Garde de Ressources

Limites strictes sur les tokens par appel, les appels par minute et le coût par session. Quand les limites sont atteintes, les appels sont bloqués — pas ralentis, pas journalisés, bloqués.

# Configured via policy YAML
enforcer = Enforcer.from_file("policy.yaml")
enforcer.record_cost(0.02)
# Raises CostLimitError if exceeded
🌐

Contrôle Réseau

Liste blanche de domaines avec support des wildcards. Les agents ne peuvent atteindre que les endpoints que vous autorisez explicitement.

network_control:
  allowed_domains:
    - "api.openai.com"
    - "*.internal.co"
# All other domains → blocked
🌊

Enforcement Streaming

Enforcement streaming AsyncIO avec lookahead. Rédaction PII et vérifications de politique sur la sortie en temps réel, pas seulement à la fin.

from enforcecore import stream_enforce

async for chunk in stream_enforce(gen):
    # PII redacted in real-time

New in v1.13

Intégration LangChain native.

Depuis v1.13, EnforceCore fournit un EnforceCoreCallbackHandler natif pour LangChain. Rédaction PII et journalisation d'audit sur chaque appel LLM — zéro changement de code dans votre chaîne.

Voir la documentation d'intégration →
langchain_demo.py 
from enforcecore.integrations.langchain import (
    EnforceCoreCallbackHandler
)
from langchain_openai import ChatOpenAI

# One line — PII redacted, audit logged
handler = EnforceCoreCallbackHandler(
    policy="policy.yaml"
)
llm = ChatOpenAI(callbacks=[handler])

result = llm.invoke("My SSN is 123-45-6789")
# SSN redacted before the LLM sees it
# Audit entry created automatically

Questions fréquentes

EnforceCore ajoute-t-il de la latence à mon agent ?

Le surcoût mesuré est de 0,056 ms P50 pour l'enforcement E2E complet (Apple Silicon, Python 3.13). Dans tout workflow d'agent réel, la latence réseau vers le LLM est quatre ordres de grandeur supérieure. La détection PII avec Presidio NER ajoute ~2 ms ; le mode regex seul reste sous 0,1 ms.

Quels frameworks d'agents sont supportés ?

Tout framework qui utilise des fonctions Python comme outils : LangChain (callback handler natif), LangGraph, CrewAI, AutoGen et Python pur. Le décorateur @enforce est agnostique du framework — il enveloppe tout callable.

EnforceCore envoie-t-il des données à des services externes ?

Non. EnforceCore s'exécute entièrement dans votre processus. Le moteur de politique, le rédacteur PII et l'auditeur Merkle n'effectuent aucun appel réseau. Les journaux d'audit sont écrits localement. Rien ne quitte votre environnement sauf si vous l'exportez explicitement.

Quelle est la licence ?

Apache 2.0. Vous pouvez utiliser, modifier et distribuer EnforceCore dans des produits commerciaux sans restriction. Pas de redevances, pas de limites d'utilisation, pas de copyleft GPL. Conditions complètes dans LICENSE.

Est-ce prêt pour la production ?

Oui. v1.14.0 est la dernière version stable — la 14e version publiée. Elle compte 2 366 tests, 97% de couverture, et un engagement de versionnement sémantique : pas de changements cassants dans la ligne 1.x sans un bump de version majeure.

Supporte-t-il les rapports de conformité ?

Oui. Depuis v1.8, EnforceCore peut exporter les pistes d'audit en rapports EU AI Act, SOC2 et GDPR via enforcecore audit export. Ce sont des rapports structurés conçus pour les auditeurs — pas juste des logs bruts.
